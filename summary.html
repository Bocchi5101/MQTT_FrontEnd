ESP ↔ HiveMQ ↔ React

สรุปจาก README และสไลด์ทั้ง 3 ไฟล์ พร้อมแนวทาง ESP8266

ดาวน์โหลดโค้ด ESP8266
อ่านก่อนใช้: บอร์ดที่คุณมีคือ ESP32 แต่โค้ดท้ายเอกสารเป็นตัวอย่างสำหรับ NodeMCU ESP8266 + DHT11 + LED ภายนอก ตามคำถามเพิ่มเติม รุ่นเซนเซอร์ของคุณยังไม่ทราบ ห้ามถือว่าเป็น DHT11 โดยอัตโนมัติ ต้องตรวจรุ่นและผังขาจริงก่อนต่อวงจร โค้ดยังไม่ได้คอมไพล์ด้วย Arduino core หรือทดสอบกับฮาร์ดแวร์จริง

1. ผลงานที่ต้องทำให้ได้

  • ESP อ่านอุณหภูมิและความชื้น ส่งขึ้นเว็บทุก 5 วินาที
  • เว็บมีค่า Temperature, Humidity, สถานะ LED และปุ่มควบคุม
  • ปุ่มจริง 1 ปุ่มกดแล้ว LED สลับติด/ดับหนึ่งครั้ง
  • เมื่อ LED เปลี่ยนจากปุ่มจริงหรือเว็บ ESP ต้องส่งสถานะกลับ ให้เว็บตรงกับสถานะที่บอร์ดสั่ง
เซนเซอร์ → ESP → HiveMQ → เว็บ
เว็บส่งคำสั่ง → HiveMQ → ESP เปลี่ยน LED → HiveMQ → เว็บอัปเดตสถานะ
ปุ่มจริง → ESP เปลี่ยน LED → HiveMQ → เว็บอัปเดตสถานะ

จำ: เว็บส่ง “คำสั่ง” แล้วรอ “สถานะจากบอร์ด” อย่าแสดงว่าไฟติดเพียงเพราะกดปุ่มสำเร็จ สถานะนี้เป็นสถานะ output ที่ซอฟต์แวร์บอร์ดสั่ง ไม่ใช่เซนเซอร์ตรวจว่า LED เปล่งแสงจริง

2. MQTT และข้อตกลงข้อมูล

Broker = คนกลาง (HiveMQ) • Publish = ส่ง • Subscribe = สมัครรับ • Topic = ชื่อช่อง • Payload = เนื้อหา • Client ID = ชื่อการเชื่อมต่อ ต้องไม่ซ้ำกับ client ที่ออนไลน์พร้อมกัน

Topic ผู้ส่ง → ผู้รับ Payload
lab/sensor/temp ESP → เว็บ 28.5
lab/sensor/humidity ESP → เว็บ 65.0
lab/led/status ESP → เว็บ ON / OFF
lab/led/control เว็บ → ESP ON / OFF

Topic แยกตัวพิมพ์ใหญ่/เล็ก และ slash นำหน้ามีความหมาย เช่น lab/led/status ไม่เท่ากับ /lab/led/status ถ้าร่วม broker กับเพื่อน ใช้ prefix เฉพาะคนเมื่ออาจารย์อนุญาต และแก้ให้ตรงกันทั้งเว็บและบอร์ด

  • QoS 0: ส่งได้เร็ว อาจสูญหาย ใช้ในตัวอย่างนี้
  • QoS 1: รับอย่างน้อยหนึ่งครั้ง อาจซ้ำ จึงควรใช้คำสั่ง ON/OFF แทน TOGGLE
  • QoS 2: ส่งมอบหนึ่งครั้งในกลไก MQTT มีขั้นตอนมากขึ้น
  • Retain: ให้ broker เก็บข้อความล่าสุดของ topic ส่งให้ผู้สมัครรับใหม่ ตัวอย่าง retain เฉพาะ LED status ไม่ retain คำสั่ง control
  • Retained status อาจเป็นค่าเก่าขณะบอร์ด offline; ไม่ใช่หลักฐานว่าบอร์ดยังออนไลน์
  • Wildcard ใช้ตอน subscribe: lab/# รับทุกระดับใต้ lab; lab/sensor/+ รับหนึ่งระดับใต้ sensor ไม่ใช้ wildcard ตอน publish

3. ESP32 ต่างจาก ESP8266 ตรงไหน

เรื่อง ESP32 ESP8266
Wi-Fi header #include <WiFi.h> #include <ESP8266WiFi.h>
เลือกบอร์ดใน IDE รุ่น ESP32 ที่ใช้จริง เช่น NodeMCU 1.0 (ESP-12E Module)
ขา อิงผังขา ESP32 รุ่นจริง NodeMCU: D1=GPIO5, D2=GPIO4, D5=GPIO14
รหัสเฉพาะชิป เช่น ESP.getEfuseMac() ESP.getChipId()
MQTT / topics / React หลักการเดิม เว็บใช้โค้ดเดิมได้หาก broker, topics และ payload เหมือนเดิม

เปลี่ยนแค่ header อาจไม่พอ: ต้องปรับ GPIO, board target, ฟังก์ชันเฉพาะชิป และระดับเปิด/ปิด LED ให้ตรงวงจร ESP8266 ใช้ Wi-Fi 2.4 GHz และอย่านำเลข D1 ไปเขียนเป็นเลข 1 เพราะ 1 หมายถึง GPIO1

4. เตรียม ESP8266 และต่อวงจรตัวอย่าง

  1. ติดตั้ง Arduino IDE และ ESP8266 board package หากยังไม่มี ใช้ Additional Boards Manager URL: https://arduino.esp8266.com/stable/package_esp8266com_index.json แล้วติดตั้ง ESP8266 ใน Boards Manager
  2. เลือกบอร์ดและพอร์ต USB ให้ตรงฮาร์ดแวร์
  3. ติดตั้ง MQTT โดย Joel Gaehwiler, DHT sensor library โดย Adafruit และ Adafruit Unified Sensor
  4. เปิดไฟล์ esp8266_iot_lab/esp8266_iot_lab.ino แก้ Wi-Fi, MQTT host, username/password แล้วกด Verify ก่อน Upload
  5. เปิด Serial Monitor ที่ 115200 baud
อุปกรณ์ตัวอย่าง ต่อกับ NodeMCU ESP8266
LED ภายนอก D1 / GPIO5 → ตัวต้านทาน 330 Ω → ขา anode LED; cathode → GND
ปุ่ม D5 / GPIO14 ↔ ปุ่ม ↔ GND ใช้ INPUT_PULLUP
DHT DATA D2 / GPIO4
DHT VCC / GND 3.3V / GND สำหรับเซนเซอร์หรือโมดูลที่รองรับ 3.3V

ตรวจป้าย VCC/DATA/GND ของโมดูลจริง ไม่เดาลำดับขาจากสีหรือรูปร่าง ถ้าเป็นเซนเซอร์เปล่าให้ต่อ pull-up DATA → 3.3V ประมาณ 10 kΩ ตามคู่มือเซนเซอร์ โมดูลบางรุ่นมีมาแล้ว GPIO ESP8266 ใช้สัญญาณ 3.3V ไม่ป้อนสัญญาณ 5V เข้าขา

โค้ดกำหนด DHTTYPE DHT11 ถ้าเป็น DHT22 ให้เปลี่ยนเป็น DHT22 ถ้าเป็นเซนเซอร์อื่น เช่น SHT ต้องเปลี่ยนไลบรารีและส่วนอ่านค่า ไม่ใช่เปลี่ยนชื่ออย่างเดียว ตัวอย่างนี้ไม่ใช้ LED บนบอร์ด ถ้าจะใช้ต้องตรวจขาและ active-low ของบอร์ดก่อน

5. อ่านโค้ด ESP ให้เข้าใจ

ส่วน หน้าที่
setup() เริ่ม Serial, ขา LED/ปุ่ม, เซนเซอร์, Wi-Fi และตั้ง MQTT callback
maintainConnections() ต่อ Wi-Fi/MQTT ใหม่เมื่อหลุด และ subscribe control อีกครั้ง
mqtt.loop() ดูแลรับข้อมูลและการเชื่อมต่อ ต้องเรียกบ่อย
messageHandler() รับ ON/OFF แล้วเรียก setLed() ไม่ publish ภายใน callback
setLed() เปลี่ยน GPIO, เก็บ ledOn และตั้งธง statusPending
readButton() อ่านปุ่ม กรองสัญญาณเด้ง 40 ms และสลับ LED เฉพาะจังหวะกด
publishSensors() อ่าน DHT ตรวจ NaN แล้วส่งค่าเมื่อ MQTT พร้อม

INPUT_PULLUP: ไม่กด=HIGH, กด=LOW • Debounce: รอค่าคงที่ก่อนยอมรับการกด • !ledOn: กลับสถานะ • statusPending: บอกว่า loop ต้องส่งสถานะล่าสุด

if (millis() - lastSensorAt >= 5000UL) {
  lastSensorAt = millis();
  publishSensors();
}

ใช้เวลาชนิด unsigned long และการลบแบบนี้เพื่อรองรับ millis() วนกลับ โค้ดไม่หยุดรอ 5 วินาที จึงยังอ่านปุ่มและรับ MQTT ระหว่างรอบได้ แต่การ connect เครือข่าย/TLS ในตัวอย่างยังเป็น synchronous และอาจหยุดการอ่านปุ่มชั่วครู่เมื่อเครือข่ายมีปัญหา การส่งทุก 5 วินาทีเป็นช่วงเวลาโดยประมาณเมื่อระบบเชื่อมต่อปกติ ไม่มีการเก็บข้อมูลย้อนหลังช่วง offline

6. HiveMQ และ React

HiveMQ Cloud ตามสไลด์: ESP ใช้ host + TLS port 8883; browser ใช้ wss://HOST:8884/mqtt ตรวจค่าของ cluster จริง Host ฝั่ง ESP ใส่เฉพาะชื่อโดเมน ไม่ใส่ https:// หรือ /mqtt

ใช้ MQTT credentials ที่อนุญาต publish/subscribe topics เหล่านี้ ไม่จำเป็นต้องเป็นรหัสเข้าเว็บไซต์ HiveMQ ตั้ง Client ID เว็บไม่ซ้ำกับบอร์ด ตัวอย่างบอร์ดสร้าง ID จาก chip ID ให้แล้ว

ในโปรเจกต์ React ที่มี package.json: npm install แล้ว npm install mqtt สั่งเปิดตาม scripts ใน package.json: CRA ใช้ npm start; โปรเจกต์ Vite โดยทั่วไปใช้ npm run dev สไลด์ใช้ CRA ซึ่งเลิกแนะนำสำหรับโปรเจกต์ใหม่แล้ว หากสอบใช้โปรเจกต์เดิมให้ยึดของอาจารย์

คำ/ไฟล์ หน้าที่
Node.js / npm รัน JavaScript นอก browser / จัดการแพ็กเกจ
package.json ข้อมูลโปรเจกต์ dependencies และ scripts
package-lock.json / node_modules บันทึก dependency versions / โฟลเดอร์แพ็กเกจที่ติดตั้ง
useState เก็บ temp, humidity, led และสถานะการเชื่อมต่อสำหรับแสดงผล
useEffect สร้าง MQTT client, ลงทะเบียน events และคืน cleanup ปิด client
on('connect') subscribe sensor/temp, sensor/humidity, led/status
on('message') แปลง message.toString() แล้วเรียก setter ตาม topic
ปุ่มเว็บ publish ON/OFF ไป led/control แบบ retain:false เมื่อเชื่อมต่อแล้ว 
const [temp, setTemp] = useState('--');
// ภายใน message handler:
if (topic === 'lab/sensor/temp') setTemp(message.toString());
// ภายใน JSX:
<p>Temperature: {temp} °C</p>

เก็บ client ให้ปุ่มเข้าถึงได้ เช่น useRef; สร้าง client ใน effect และ cleanup client ตัวเดียวกัน อย่าเชื่อมต่อใหม่ทุกครั้งที่ temp เปลี่ยน ปุ่มเว็บควร disabled ขณะยังไม่เชื่อมต่อ และปุ่ม toggle ควรรอรู้สถานะ LED ก่อน

ตัวอย่างนี้ส่ง plain text แยก topic จึงไม่ต้อง JSON.parse ค่า ON/OFF หากโจทย์ให้ JSON รวม เช่น {"temp":28.5,"humidity":65} ต้องเปลี่ยนทั้งผู้ส่งและผู้รับให้ตรงกัน และจัดการ JSON ที่อ่านไม่ได้

  1. LED + ปุ่มทำงานโดยไม่ใช้ network

  6. ส่ง ON/OFF ผ่าน broker แล้ว LED จริงเปลี่ยน พร้อม status กลับ

  8. ทดสอบปุ่มเว็บ → LED → status และปุ่มจริง → LED → status

9. จุดในสไลด์ที่ควรแก้ความเข้าใจ

  • ตัวอย่างแต่ละบทใช้ topic ต่างกัน ต้องรวมให้ตรงตาม README
  • WiFi.status() คืนสถานะการเชื่อมต่อ ไม่ใช่จำนวนเครือข่าย; scanNetworks() ใช้สแกนเครือข่าย
  • JavaScript: var มี function scope ไม่ใช่ global เสมอ; for ปกติใช้ semicolon คั่น เช่น for (let i=0; i<3; i++)
  • Bitwise NOT คือ ~; logical NOT คือ !; npm remove คือถอนแพ็กเกจ
  • React render ได้จากหลายสาเหตุ เช่น state, parent render หรือ context ไม่ใช่เฉพาะ state ของตัวเองเท่านั้น
  • useEffect ไม่มี dependency array ทำงานหลังทุก commit; [] ใช้กับการตั้งค่าที่ไม่มี reactive dependency และ StrictMode อาจทดสอบ setup/cleanup เพิ่มใน development
  • ตัวอย่าง TLS ใช้ setInsecure() ตามแนวแลบ: เข้ารหัสแต่ข้ามการยืนยันใบรับรองเซิร์ฟเวอร์ งานจริงควรตั้ง trusted CA; รหัสในหน้าเว็บผู้ใช้มองเห็นได้ จึงใช้ credentials สำหรับแลบที่จำกัดสิทธิ์

10. คำถามทบทวนก่อนสอบ

  1. ใคร subscribe led/control? ESP
  2. ใคร publish led/status? ESP หลังสั่ง LED
  3. ทำไมใช้ millis()? ให้ loop ยังอ่านปุ่มและ MQTT ระหว่างรอรอบเซนเซอร์
  4. กดปุ่มจริงแล้วเว็บเปลี่ยนได้อย่างไร? ESP publish status → broker → เว็บ setState
  5. เว็บต้องเปลี่ยนไหมเมื่อเปลี่ยน ESP32 เป็น ESP8266? ไม่ต้อง ถ้า broker/topics/payload เหมือนกัน
  6. ยังไม่รู้รุ่นเซนเซอร์ เขียนส่วนไหนได้ก่อน? Wi-Fi, MQTT, LED, ปุ่ม และ React; ส่วนอ่าน sensor ต้องเลือกรุ่นให้ถูก

ภาคผนวก: โค้ด ESP8266

เปิดไฟล์ .ino ที่แนบแยกใน Arduino IDE ได้โดยตรง โค้ดนี้ใช้วงจรในข้อ 4 และ DHT11 เป็นสมมติฐาน ต้องแก้ค่าขึ้นต้น YOUR_ ก่อนใช้งาน

/* IoT lab example: NodeMCU ESP8266 + DHT11 + external LED + button.
   Install MQTT by Joel Gaehwiler, DHT sensor library by Adafruit,
   and Adafruit Unified Sensor. Select the actual ESP8266 board.
   Set credentials below. This sketch has NOT been hardware-tested.
   D1=GPIO5 LED (active HIGH), D2=GPIO4 DHT DATA, D5=GPIO14 button.
   If the actual sensor is DHT22, change DHTTYPE. Other sensors need
   their own library and read code. All IO signals must be 3.3V.
*/
#include <ESP8266WiFi.h>
#include <WiFiClientSecure.h>
#include <MQTTClient.h>
#include <DHT.h>

const char* WIFI_SSID = "YOUR_WIFI_SSID";
const char* WIFI_PASSWORD = "YOUR_WIFI_PASSWORD";
const char* MQTT_HOST = "YOUR_CLUSTER.s1.eu.hivemq.cloud";
const int MQTT_PORT = 8883;
const char* MQTT_USERNAME = "YOUR_MQTT_USERNAME";
const char* MQTT_PASSWORD = "YOUR_MQTT_PASSWORD";

// Use the same topics in React. Add your student ID if sharing a broker.
const char* TOPIC_TEMP = "lab/sensor/temp";
const char* TOPIC_HUMIDITY = "lab/sensor/humidity";
const char* TOPIC_STATUS = "lab/led/status";
const char* TOPIC_CONTROL = "lab/led/control";

const uint8_t LED_PIN = 5;      // NodeMCU D1 (external LED)
const uint8_t DHT_PIN = 4;      // NodeMCU D2
const uint8_t BUTTON_PIN = 14;  // NodeMCU D5, button to GND
const bool LED_ACTIVE_LOW = false;
#define DHTTYPE DHT11

WiFiClientSecure networkClient;
MQTTClient mqtt(256);
DHT dht(DHT_PIN, DHTTYPE);
String clientId;
bool ledOn = false;
bool statusPending = true;
bool previousRawButton = HIGH;
bool stableButton = HIGH;
bool wifiWasConnected = false;
unsigned long buttonChangedAt = 0;
unsigned long lastSensorAt = 0;
unsigned long lastWifiAttemptAt = 0;
unsigned long lastMqttAttemptAt = 0;
const unsigned long SENSOR_INTERVAL = 5000;
const unsigned long DEBOUNCE_MS = 40;

void setLed(bool on) {
  ledOn = on;
  digitalWrite(LED_PIN, (on != LED_ACTIVE_LOW) ? HIGH : LOW);
  statusPending = true;
  Serial.print("LED: ");
  Serial.println(on ? "ON" : "OFF");
}

void messageHandler(String &topic, String &payload) {
  Serial.println(topic + " -> " + payload);
  if (topic != TOPIC_CONTROL) return;
  if (payload == "ON") setLed(true);
  else if (payload == "OFF") setLed(false);
  // Publish later in loop(), not inside this callback.
}

void readButton() {
  bool raw = digitalRead(BUTTON_PIN);
  unsigned long now = millis();
  if (raw != previousRawButton) {
    previousRawButton = raw;
    buttonChangedAt = now;
  }
  if (now - buttonChangedAt >= DEBOUNCE_MS && raw != stableButton) {
    stableButton = raw;
    if (stableButton == LOW) setLed(!ledOn);
  }
}

void maintainConnections() {
  unsigned long now = millis();
  if (WiFi.status() != WL_CONNECTED) {
    if (wifiWasConnected) {
      wifiWasConnected = false;
      networkClient.stop();
      Serial.println("Wi-Fi lost");
    }
    if (now - lastWifiAttemptAt >= 10000UL) {
      lastWifiAttemptAt = now;
      WiFi.begin(WIFI_SSID, WIFI_PASSWORD);
      Serial.println("Retrying Wi-Fi...");
    }
    return;
  }
  if (!wifiWasConnected) {
    wifiWasConnected = true;
    Serial.print("Wi-Fi IP: ");
    Serial.println(WiFi.localIP());
    lastMqttAttemptAt = now - 5000UL;
  }
  if (mqtt.connected() || now - lastMqttAttemptAt < 5000UL) return;
  lastMqttAttemptAt = now;
  Serial.println("Connecting MQTT...");
  // connect() is synchronous: an individual connection attempt may pause
  // button polling. The retry interval avoids an endless retry while-loop.
  if (mqtt.connect(clientId.c_str(), MQTT_USERNAME, MQTT_PASSWORD)) {
    if (!mqtt.subscribe(TOPIC_CONTROL)) {
      Serial.println("Subscribe failed; check permissions");
      mqtt.disconnect();
      return;
    }
    statusPending = true;
    Serial.println("MQTT connected, control subscribed");
  } else {
    Serial.print("MQTT failed, error: ");
    Serial.println(mqtt.lastError());
  }
}

void publishSensors() {
  float humidity = dht.readHumidity();
  float temperature = dht.readTemperature();
  if (isnan(humidity) || isnan(temperature)) {
    Serial.println("DHT read failed: check type, DATA pin and wiring");
    return;
  }
  Serial.print("Temperature C: "); Serial.print(temperature);
  Serial.print(" | Humidity %: "); Serial.println(humidity);
  if (mqtt.connected()) {
    bool tempSent = mqtt.publish(TOPIC_TEMP, String(temperature, 1));
    bool humiditySent = mqtt.publish(TOPIC_HUMIDITY, String(humidity, 1));
    if (!tempSent || !humiditySent) Serial.println("Sensor publish failed");
  }
}

void setup() {
  Serial.begin(115200);
  digitalWrite(LED_PIN, LED_ACTIVE_LOW ? HIGH : LOW);
  pinMode(LED_PIN, OUTPUT);
  pinMode(BUTTON_PIN, INPUT_PULLUP);
  previousRawButton = stableButton = digitalRead(BUTTON_PIN);
  dht.begin();
  setLed(false);
  clientId = "esp8266_" + String(ESP.getChipId(), HEX);
  WiFi.mode(WIFI_STA);
  WiFi.begin(WIFI_SSID, WIFI_PASSWORD);
  lastWifiAttemptAt = millis();
  // Classroom shortcut matching the slides: encrypted transport but no
  // server certificate authentication. For production use a trusted CA.
  networkClient.setInsecure();
  mqtt.begin(MQTT_HOST, MQTT_PORT, networkClient);
  mqtt.onMessage(messageHandler);
}

void loop() {
  readButton();
  maintainConnections();
  if (mqtt.connected()) mqtt.loop();
  readButton();
  if (mqtt.connected() && statusPending) {
    if (mqtt.publish(TOPIC_STATUS, ledOn ? "ON" : "OFF", true, 0)) {
      statusPending = false;
    }
  }
  unsigned long now = millis();
  if (now - lastSensorAt >= SENSOR_INTERVAL) {
    lastSensorAt = now;
    publishSensors();
  }
  delay(10); // Briefly yield; do not use delay(5000) for sensor timing.
}
